# tcp-sansio

[![CI](https://github.com/AngeloHH/tcp-sansio/actions/workflows/ci.yml/badge.svg)](https://github.com/AngeloHH/tcp-sansio/actions/workflows/ci.yml)
[![PyPI](https://img.shields.io/pypi/v/tcp-sansio)](https://pypi.org/project/tcp-sansio/)
[![Python versions](https://img.shields.io/pypi/pyversions/tcp-sansio)](https://pypi.org/project/tcp-sansio/)
[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue)](#license)

`tcp-sansio` exposes TCP connections to Python without opening operating-system
sockets or creating TUN/TAP adapters. Applications provide raw IPv4 packets,
advance time, and collect the IPv4 packets generated by the stack.

The public Python API isolates applications from the TCP engine supplied by
`smoltcp`. Each `TCPStack` owns an independent address space, making overlapping
virtual networks possible inside the same process. The API remains experimental
while the package is in the `0.x` series.

## Installation

```
pip install tcp-sansio
```

Prebuilt wheels are published for Linux (glibc and musl), Windows and macOS on
x86-64 and ARM, and work on CPython 3.10 and newer. Other platforms build from
the source distribution, which needs a [Rust toolchain](https://rustup.rs/).

The stack currently speaks IPv4 and TCP only.

## Quick start

Two stacks can talk to each other inside one process: every packet one of them
transmits is handed to the other one.

```python
from tcp_sansio import TCPStack

client = TCPStack("10.0.0.2", clock=None)
server = TCPStack("10.0.0.1", clock=None)
now = 0.0

def run(milliseconds=10):
    global now
    for _ in range(milliseconds):
        now += 0.001
        for packet in client.transmit(now): server.receive(packet, now)
        for packet in server.transmit(now): client.receive(packet, now)

listener = server.listen(7)
outgoing = client.connect("10.0.0.1", 7)
run()
incoming = listener.accept()

outgoing.send(b"hello")
run()
incoming.send(incoming.receive().upper())
run()
print(outgoing.receive())  # b'HELLO'
```

The full version, including the shutdown, is in
[`examples/loopback.py`](https://github.com/AngeloHH/tcp-sansio/blob/main/examples/loopback.py).

## Usage

In a real application the packets come from and go to a VPN, a TUN device or
any other transport the application already owns:

```python
from tcp_sansio import TCPStack

stack = TCPStack('10.20.0.1', mtu=1420)
listener = stack.listen(80, backlog=16)

stack.receive(ip_packet)
for packet in stack.transmit():
    vpn.send(packet)

connection = listener.accept()
if connection:
    request = connection.receive()
    connection.send(http_server.handle(request))

for event in stack.events():
    if event.readable: consume(event.connection.receive())
    if event.writable: resume_sending(event.connection)
    if event.eof: event.connection.close()
```

The application must call `advance()` when `next_timeout()` expires so TCP
retransmissions and connection timers continue even when no packet arrives.
No method opens a socket, starts a thread, or accesses a network adapter.

Calls may omit `timestamp` and use the stack's monotonic clock, or always pass
explicit seconds from one monotonic clock. A stack rejects mixing both modes.
Pass `clock=None` to require explicit timestamps, which is useful in simulations.

Connections and listeners support `with` and explicit `release()`/`close()`.
Dropping their last Python reference also releases the native resource.
Releasing a connection after `close()` lets the stack finish the FIN handshake
in the background, so queued data is still delivered; the stack gives up and
sends a reset after 120 seconds. Releasing a connection that was not closed
aborts it, and the reset is emitted by the next `transmit()`. Closing a
listener resets the connections it had not handed to `accept()` yet.

`events()` reports `readable` while received data is buffered. `writable` is
reported once when an outgoing connection is established and once when a
short `send()` can continue. `eof` is reported once, after all received data
was read, when the peer finished or reset the connection; `connection.state`
tells both cases apart.

`stack.close()` resets every connection and returns the final packets, which
the application should still deliver.

## Intercepting connections

A stack created with `any_ip=True` receives packets for every destination,
which lets a VPN server terminate its clients' connections to the internet.
`intercept()` takes a client's SYN and answers it as the destination it was
addressed to; `local_address` is that destination and `remote_address` the
client. A SYN that is passed to `receive()` without being intercepted is
refused with a reset, as is any packet for a connection the stack does not know.

```python
egress = TCPStack('10.20.0.254', mtu=1420, any_ip=True)

# Hold the SYN until the application reached the real destination.
if upstream_connected:
    connection = egress.intercept(syn)
else:
    egress.receive(syn)  # Answered with a reset.
```

Holding the SYN until the real destination answers keeps a refused or
unreachable destination from looking connected. An `any_ip` stack only accepts
TCP: smoltcp would otherwise answer pings on behalf of every address. Listeners
keep the stack's own address, so they never catch intercepted traffic.
